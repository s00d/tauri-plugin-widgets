# Development guide

Contributor docs for **tauri-plugin-widgets**. For app integration, start at the [Guide](/guide) (install, first widget, platform setup).

## Architecture

The plugin is a **library**, not a widget builder. You own the extension / provider target; the plugin supplies storage, reload, and renderers.

| Component | Role |
|-----------|------|
| **Rust** (`src/`) | Storage, FFI, reload, desktop windows, Adaptive Cards, receipts |
| **Swift** (`swift/TauriWidgets`) | SwiftUI WidgetKit views / models / store |
| **Android** (`android/`) | Jetpack Glance renderer + receivers |
| **Desktop HTML** (`widget.html`) | Frameless webview renderer (embedded via `widgetview`; users do not copy it by default) |
| **Adaptive Cards** (`src/adaptive_card.rs`) | IR → Adaptive Cards 1.5 (Windows Widgets Board) |
| **Linux pin** (`src/linux/`) | X11 `_NET_WM_*` desktop hints; optional `layer-shell` |
| **Templates** (`templates/`) | iOS / macOS / Windows starters → copied into `src-tauri/*-widget/` by CLI |

**Data flow:** `setWidgetConfig(json, group, widgetId)` → platform storage (`nonce`) → reload / Glance / Widgets Board → native UI for that `widgetId`.

### Apple transport drivers

Host writes use **one** driver from `plugins.widgets.transport` (`appGroup` | `userDefaults` | `widgetContainer` | `auto`). See [Apple data transport](/guide/transport).

| Piece | Role |
|-------|------|
| [`src/config.rs`](https://github.com/s00d/tauri-plugin-widgets/blob/main/src/config.rs) | `WidgetsPluginConfig` / `TransportKind` |
| [`src/transport.rs`](https://github.com/s00d/tauri-plugin-widgets/blob/main/src/transport.rs) | `Transport` trait, `build_driver`, `probe_once` |
| [`src/macos_transport.rs`](https://github.com/s00d/tauri-plugin-widgets/blob/main/src/macos_transport.rs) | Concrete file / UserDefaults drivers |
| Swift `WidgetDataStore` | Extension still multi-reads + freshest pick |

Receipts are diagnostics (`getWidgetDiagnostics`), not a runtime selector. Unit tests: `cargo test -p tauri-plugin-widgets transport::`.

Storage keys (0.4+): `config:{widgetId}`, `pending_actions`, `__meta_nonce__`, `__meta_updated_at__`. Windows also `ac:template:{widgetId}` / `ac:data:{widgetId}`.

## Codegen

After changing Rust IR (`src/models.rs` / capabilities):

```bash
pnpm codegen
# or: cargo run --bin gen-ts --features codegen
```

## Visual / golden tests

Rules and runners: [`visual-stand.md`](/contributing/visual-stand).

```bash
just test-macos-visual
just record-macos weather.small          # CASE + GOLDEN_RECORD=1
# iOS ImageRenderer:
CASE=weather.small GOLDEN_RECORD=1 just record-ios weather.small

pnpm audit:sheets                        # → out/audit/index.html
```

Windows PNG goldens: record on a Windows VM (`just record-windows <case>`), not a Mac SVG compositor. See [`windows-surfaces.md`](/contributing/windows-surfaces).

Adaptive Cards JSON snapshots:

```bash
pnpm -C scripts cli gen-adaptive-snapshots
FEATURES=rasterize pnpm -C scripts cli gen-adaptive-snapshots   # chart/canvas data-URIs
```

## Tests and CI

| What | Local | CI (`.github/workflows/ci.yml`) |
| --- | --- | --- |
| Rust, all features | `pnpm test:rust` / `pnpm test:rust:nextest` | ubuntu (nextest `ci` profile, JUnit artifact) + `windows-latest` |
| Plugin commands over IPC (`tauri::test` mock runtime + real ACL from `permissions/`): model test + stories | `cargo test --test offline_model` (model), `cargo test --test activities` etc. (stories) | same as above |
| Mobile targets | `cargo check --lib --target aarch64-linux-android` (or `aarch64-apple-ios`) | `mobile-targets` |
| Swift package | `pnpm test:swift` | `swift` (macOS) + `ios-build` (`xcodebuild`, iOS Simulator) |
| Windows widget template | `dotnet build templates/windows-widget/<proj>/<proj>.csproj -p:Platform=x64` | `windows` |
| Desktop renderer (Playwright) | `pnpm test:desktop:linux` (Docker) | `playwright`, pinned image = `@playwright/test` version |
| CLI | `pnpm test:cli`; `pnpm test:ios:e2e` builds the generated WidgetExtension (macOS, Xcode, xcodegen) | `test` |

`.config/nextest.toml` quarantines tests that depend on wall-clock TTLs, a local HTTP stub or
shared files: they retry twice and a pass on retry is reported as `FLAKY`. Fix the test and
remove it from the filter instead of adding more.

Mutation tools (cargo-mutants, Stryker, PIT, Muter) run locally only, not in CI. See
[Mutation testing](/contributing/mutation-testing).

## Android notes

- Rendering path is **Jetpack Glance**.
- Prefer flat `vstack` / `hstack` trees; deep `container` nesting is flaky on some launchers.
- Always set `progress.label` so hosts never show `null`.

## Documentation site

The site is a standalone Nuxt app in `docs/` (Nuxt 4, Nuxt UI, Nuxt Content; own `pnpm-lock.yaml`, not a root workspace package). Pages live in `docs/content/` (numeric prefixes only order the sidebar). JS reference, Tauri commands, permissions and changelog pages are written by `docs/scripts/generate.mjs` on every build. Diagrams: edit `docs/diagrams/*.mmd`, then `pnpm -C docs diagrams` re-renders the committed SVGs in `docs/public/diagrams/` (needs Chrome). Illustrations: `docs/public/illustrations/<name>.light.svg` come from fal (`node docs/scripts/illustrations.mjs --generate <name>`, prompts in that script); the script writes the `.dark.svg` twin by recoloring. Maintainer tooling is `@tauri-plugin-widgets/scripts` (citty + TypeScript under `scripts/src`).

**Boundary:** consumer commands (`preview`, `signing`, `doctor`, …) live in `src-cli/` → published `dist-cli/cli.mjs`. Visual stands / goldens / docs codegen live under `scripts/` (`pnpm hosts`, `pnpm cli:test`). See root [README](https://github.com/s00d/tauri-plugin-widgets/blob/main/README.md) and [scripts/README.md](https://github.com/s00d/tauri-plugin-widgets/blob/main/scripts/README.md).

```bash
pnpm docs:generate   # gallery, elements, shots, schemas → docs/public + marker blocks
pnpm docs:check      # generated-docs drift + schema description audit
pnpm docs:audit      # every schema element / property has a description
pnpm -C docs install # once: docs dependencies
pnpm docs:dev        # generate + nuxt dev
pnpm docs:build      # generate + static site in docs/.output/public
pnpm -C scripts cli --help          # all maintainer commands
pnpm -C scripts typecheck
pnpm test:cli                       # consumer CLI behavior fixtures
```

Root aliases (`pnpm triage`, `pnpm ios-up`, `pnpm build:example`, …) call `pnpm -C scripts cli …`. Bash/PowerShell stands live under `scripts/sh/` and `scripts/win/`; citty only `spawn`s them.

Generated trees (`docs/public/shots/**`, showcase/elements marker bodies) are rebuilt by `pnpm docs:generate`.
